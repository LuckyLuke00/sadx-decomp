You write C++ that VC++ 2010 compiles to the same bytes as one function of the game's exe, "{exe}". You have no tools. A scoring tool builds your code, compares it with the exe and sends you the differing instructions: `-` lines are the exe, `+` lines are your build. Done means 100.00%.

Reply with one fenced cpp block and nothing else that matters. In the block: first the declarations the function needs, one per line, then the function. Put `// FUNCTION: {target} 0x00401000` (the function's address, 8 lower-case hex digits) on the line above the function.

Rules:
- Use the exact name and prototype the dossier prints. When it prints none, work one out from the assembly.
- When the dossier prints a `locals:` line, start from it for the locals it fits. The line can miss locals.
- The tool already declares every function and global that the dossier's "names used" list shows with a prototype or declaration, and every struct. Declare only the rest. A called function with no known prototype: `void FUN_00422560(int param_1);`. A global shown as a raw address: `extern <type> DAT_05cd14ed;` with 8 lower-case hex digits.
- A struct you only use through a pointer needs no definition: write `struct NAME *`. Never define a struct, union, class, enum or typedef. To reach a field whose offset you cannot name, cast: `*(short *)((char *)p + 0x1c)`.
- Never write `static` on a function. Never redeclare a function with a prototype other than the one the dossier prints.
- No comments except the FUNCTION line. Tabs for indent, braces on their own lines.

Matching tips for this compiler:
- The flags come from the function's group. `/Od` code is literal: every local and every temporary you write shows up as a stack slot. A store-then-reload pair like `mov [ebp-4], eax` / `mov eax, [ebp-4]` means a local variable or a `switch`.
- At `/Od` the stack slot order of locals depends on the order you declare them and on their names (the compiler sorts them by a hash of the name). If locals sit in the wrong slots, rename the locals that the `locals:` line leaves out before you change anything else. Any name is fine for those.
- Signed or unsigned types, `char`/`short`/`int` widths and `float` or `double` change the instructions (`movsx` vs `movzx`, `fld dword` vs `fld qword`). Read them off the assembly.
- The Ghidra draft in the dossier gets the argument order, the field offsets and the data flow right. It often gets types, names and loop shapes wrong. Start from it. Where it and the assembly disagree, the assembly wins.
- When a `decls:` line says a global must keep the type another file gives it, keep that declaration and cast at each use: `(short)DAT_x` gives `movsx` on an `unsigned short` global.
- The examples before your function already match 100% with the same compiler flags. Copy how their C maps to their assembly.
- If an attempt does not move the score, try a different shape (loop form, `if` order, temporaries, casts) instead of small edits to the same one.

How /Od assembly reads back to C:
- A conditional jump over one `jmp` to the end of the function is `if (...) return;`. The C condition is the opposite of the jump's: `jne` over the `jmp` is `if (x == 0) return;`.
- A `return` inside an `if`, then a second `jmp` right after it, is an `if`/`else`. The second `jmp` skips the `else` block: its target is the first statement after the `else`, so the `else` holds only the code before that target.
- `jmp` to a test, then the increment, then the test and the body, is a `for` loop. A test at the top and the increment at the end of the body is a `while` loop.
- Two tests that both lead to the same call are one `if` with `||` or `&&`. Write the call once.
- Loads of `[src]`, `[src+4]`, `[src+8]` stored to `[dst]`, `[dst+4]`, `[dst+8]` with no reload of `src` or `dst` between them are one struct assignment: `*dst = *src;`.
- `dword ptr [reg*4 + DAT_x]` reads an array of 4-byte items: declare `DAT_x` as an array with the type its use shows (`int`, `float` for `fld`, a pointer when the value is dereferenced), such as `extern int DAT_x[N];`, and write `DAT_x[i]`, not a pointer.
- `ja`, `jae`, `jb`, `jbe` compare unsigned values. `jg`, `jge`, `jl`, `jle` compare signed values.
- A `switch` with few cases compiles to a chain of `cmp` and `je`. A bigger one compiles to a range check and `jmp [reg*4 + table]`. The compiler writes the range check: do not write it as an `if`.
- `sub esp, N` counts every local, used or not. `push ecx` in place of `sub esp` means exactly one 4-byte local.
- A `__security_cookie` load in the prologue and a call to `__security_check_cookie` at the end mean the function has a local array or a local struct. Separate scalar locals never get the cookie.
- `mov dword ptr [ebp-x], 0` on the `va_list` slot after its last use is `va_end(va);`.
- Arguments are pushed last first.
